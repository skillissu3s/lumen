# Brief 09 — Docker, CI, releases, GitHub Pages

Read `AGENTS.md`, `docs/ARCHITECTURE.md`, `server/config.js` (env vars). Create ONLY: `Dockerfile`, `.dockerignore`, `docker-compose.yml`, `docker-entrypoint.sh`, `.env.example`, `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `.github/workflows/pages.yml`.

- **Dockerfile** (multi-stage, `node:24-alpine`): build stage `ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci` + `npm run build`; runtime stage installs `git tini su-exec ca-certificates`, `git config --system --add safe.directory '*'`, `npm ci --omit=dev`, copies `server/ shared/ plugins/ dist/ package*.json`, `ENV NODE_ENV=production PORT=3000 DATA_DIR=/data NODE_OPTIONS=--disable-warning=ExperimentalWarning`, `VOLUME /data`, `EXPOSE 3000`, `HEALTHCHECK` hitting `/healthz` with wget, entrypoint that chowns `/data` to `node` and drops privileges with `su-exec node`, `CMD ["node","server/index.js"]`.
- **docker-compose.yml**: service `lumen`, build `.`, port `3000:3000`, `env_file: .env`, named volume `lumen-data:/data`, `restart: unless-stopped`.
- **.env.example**: every env var from `server/config.js` with a one-line comment each (APP_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD, ADMIN_NAME, PUBLIC_URL, PORT, DATA_DIR, SESSION_DAYS, INVITE_DAYS, MAX_FILE_MB, SECURE_COOKIES, TRUST_PROXY).
- **ci.yml**: on push/PR to main: ubuntu, node 24, `npm ci` (with `ELECTRON_SKIP_BINARY_DOWNLOAD=1`), `npm test`, `npm run build`.
- **release.yml**: on tag `v*` and manual: matrix windows/macos/ubuntu, node 24, `npm ci`, `npx vite build`, `npx electron-builder --publish always` with `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}`, `permissions: contents: write`, fail-fast false. Comment at the top explaining: push `vX.Y.Z` matching package.json → draft release with installers; publish it on GitHub to make it "latest".
- **pages.yml**: deploy the static build to GitHub Pages (GitHub mode — no server): on push to main + manual; `npm ci` (skip electron download), `npm run build`, upload `dist/` with `actions/upload-pages-artifact`, deploy with `actions/deploy-pages`; permissions `pages: write, id-token: write`; concurrency group `pages`. Comment: enable Pages → Source: GitHub Actions in the repo settings; the site then works in GitHub mode only (sign in with a token, data in your repo).

Use current major versions of the official actions (`actions/checkout@v4`, `actions/setup-node@v4`, `actions/upload-pages-artifact@v3`, `actions/deploy-pages@v4`). Done when the files exist and `docker build` syntax is sane (you can't run Docker here — just review carefully). Report.
