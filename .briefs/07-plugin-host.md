# Brief 07 — plugin host (sandbox, SDK, permissions, installer)

Read `AGENTS.md`, `docs/PLUGINS.md` (the contract — implement it exactly), `docs/STORAGE.md`, and the client code you use (real exports): `client/src/store/{session,workspace,derived,prefs,ui}.js`, `client/src/lib/{actions,router}.js`, `client/src/storage/github.js` (GitHub helpers), `client/src/components/ui/`, `shared/{items,calendar,dates}.js`. Look at `plugins/_dev/mock-lumen.js` — the real SDK must offer the same API. Create ONLY `client/src/plugins/**` and replace the stub `client/src/views/PluginView.jsx` (default export, `{ route }`, route `/plugin/<id>`). Also create `plugins/registry.json`. If you must touch shell/store files, keep it minimal and report it.

## Pieces
1. **`plugins/registry.json`** — the catalog: `{ "plugins": [{ "id": "focus-forest", "path": "focus-forest" }, { "id": "usage-monitor", "path": "usage-monitor" }] }`. The app reads `catalog/registry.json`, then `catalog/<path>/manifest.json` and its files (served by the server at `/catalog/` and copied into `dist/catalog/` by the Vite build — both relative to the app, so use relative URLs `catalog/...`).
2. **`client/src/plugins/manifest.js`** — `validateManifest(obj)` → `{ ok, errors, manifest }` (id pattern, required fields, `files` includes `entry`, known permissions only, ≤ 50 files, icon names are strings).
3. **`client/src/plugins/sdk.js`** — exports `SDK_SOURCE`: the JavaScript text injected into every plugin frame, defining `window.lumen` exactly as in PLUGINS.md over `postMessage` RPC to `parent` (`{ lumen: 1, id, method, params }` → reply `{ lumen: 1, id, result | error }`), plus `lumen.on(event, fn)` fed by `{ lumen: 1, event, data }` messages. It also applies theme tokens it receives to `document.documentElement.style` and sets `data-theme`.
4. **`client/src/plugins/frame.js`** — `buildSrcdoc({ manifest, files /* {name: text} */, permissions, theme })`: parse the entry HTML (DOMParser), remove `script[data-lumen-dev]`, inline local `<script src>` and `<link rel=stylesheet href>` from `files` (anything not in `files` or non-relative → removed), inject at the top of `<head>`: CSP meta (`default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; connect-src ${network ? 'https:' : "'none'"}; base-uri 'none'; form-action 'none'`), `<meta charset>`, a `<style>` with base `html,body{margin:0;font-family:var(--font);background:var(--bg);color:var(--text)}`, and the SDK script. Return the HTML string. Unit-test it (`frame.test.js` — you may use a tiny regex-based fallback if DOMParser is unavailable in node; prefer making the transform work on a string with a small HTML tokenizer so tests run in node).
5. **`client/src/plugins/host.js`** — the bridge. `PluginHost` manages one `<iframe sandbox="allow-scripts allow-forms" srcdoc=…>` per **enabled** plugin, created lazily when its view is first opened, or at app start if `background: true`. The iframes live in a hidden container in the shell (`<PluginFrames />` component that the shell renders once; when a plugin view is open, its iframe is positioned over the view's content box — e.g. render it inside a portal target the `PluginView` provides, or absolutely position it over that box — **without reloading it**: never move an iframe in the DOM (that reloads it); keep it in the container and position/size it over the view with `getBoundingClientRect` + `ResizeObserver`, hidden with `visibility:hidden` + `pointer-events:none` when not shown).
   - Validate `event.source === iframe.contentWindow` for every message; ignore others.
   - **Permissions**: each method requires one (`storage` always; `tasks.*` read/write; `calendar.*`; `notify`; `ui.setStatus` needs `statusBar` in the manifest; `system.activity.*` needs `system:activity` and the desktop bridge; `network` only affects CSP). Granted = `lumen.json.plugins[id].permissions`. Reject others with an error `"Permission <x> not granted"`.
   - **storage**: files under `data/plugins/<id>/<handle>/` through the workspace store (`ensure`, `edit`, `createFile`, `removeFile`; `list(prefix)` from `paths`). Validate names (no `..`, ≤ 200 chars, text extensions only). `get/set` use `<key>.json`.
   - **tasks**: `list(filter)` over `selectAllItems` (kind task; filters open/date/from/to/tag/list/q), `lists()`, `create` (via `addTask` with fields), `update(path, id, patch)`, `complete(path, id)` (via actions; emits `task.completed` to all plugins). Return plain JSON (strip Maps/functions).
   - **calendar**: `list({from,to})` via `expand` over visible items, `create` via `addEvent`.
   - **notify**: an in-app toast + a system notification (`Notification` API if permission granted — ask once when a plugin first notifies; on the desktop app `window.lumenDesktop?.notify` if present).
   - **ui**: `setStatus` → `useUI` `pluginStatus[id]`; `setBadge` → `pluginBadges[id]`; `open` → navigate to `/plugin/<id>`.
   - **system.activity**: forward to `window.lumenDesktop.activity.{status,day,setTracking}` (the desktop preload — another agent adds it); `status()` returns `{ available: false }` when absent.
   - **events** sent to frames: `theme` (on load and whenever theme/accent changes: send all `--*` custom properties computed on `document.documentElement`), `visibility` (its view shown/hidden), `app-focus` (window focus/blur), `command` (palette command run), `task.completed`.
   - **commands**: register each manifest command in the palette via `registerCommands('plugin:<id>', …)` titled `<Plugin name>: <title>`; running it sends `command` (and loads the frame if needed).
   - Rate-limit RPC per plugin (e.g. 50 calls/s) and cap message size (1 MB) so a broken plugin can't freeze the app.
6. **`client/src/plugins/install.js`** —
   - `loadCatalog()` → list of `{ manifest, source: 'catalog', installed, updateAvailable }`.
   - `fetchFromGitHub('owner/repo[/sub/path][@ref]')` → manifest + files via `https://api.github.com/repos/{o}/{r}/contents/{path}?ref=` (use the GitHub token if in GitHub mode, else unauthenticated) — files decoded from base64.
   - `readFromFolder(FileList)` (from `<input type=file webkitdirectory>`) → manifest + files.
   - `installPlugin({ manifest, files }, grantedPermissions)` → writes every file to `plugins/<id>/<name>` and records `{ version, permissions, source }` in `lumen.json.plugins[id]` (edit as JSON); `uninstallPlugin(id)` removes the files and the entry (data stays); `updatePlugin` = install over (asks again if permissions grew).
   - Size limits: 512 KB per file, 2 MB total; text files only.
7. **`client/src/plugins/PluginSettings.jsx`** (rendered by Settings → Plugins; another agent builds the Settings page and imports this default export) — Installed (name, version, description, permissions as readable phrases, Enable/Disable toggle for **me** → `prefs.plugins.disabled`, Update, Uninstall [admin only in server mode]), Catalog (Install), "Install from GitHub" (input `owner/repo/path`), "Install from folder" (directory picker). Installing shows a Dialog listing the permissions in plain words ("Read your tasks", "See which apps you use on this computer", "Connect to the internet", …) with Install / Cancel. Non-admins in server mode see the list read-only with only their own enable toggle.
8. **`PluginView.jsx`** — header (icon, name, "…" menu: Reload plugin, Plugin settings → `#/settings/plugins`), and the content box the frame is positioned over. Unknown/disabled plugin → EmptyState with a link to Settings → Plugins.
